# targetmap

**targetmap** - инструмент для пассивного сбора открытых данных об организациях и расчёта индекса приоритета наблюдения.  

Проект объединяет сведения о внешней инфраструктуре, почтовом канале, доменах-двойниках, поставщиках и государственных контрактах. На их основе формируются наблюдения, рассчитываются показатели и создаются карточки организаций.

Инструмент предназначен для аналитической оценки по открытым источникам. Индекс показывает относительный приоритет наблюдения внутри выборки и **не является вероятностью успешной атаки**.

## Принцип работы

Обработка разделена на три этапа:

1. **Сбор данных.** Сборщики получают сведения из открытых источников и сохраняют исходные ответы в JSON-снимки с датой.
    
2. **Нормализация.** Снимки преобразуются в наблюдения. Проверяется принадлежность адресов организации, применимость признаков и наличие подтверждённых зависимостей.
    
3. **Расчёт.** Наблюдения объединяются по заданным весам. Для каждого объекта рассчитывается индекс и формируется аналитическая карточка.
    

Состояние каждого наблюдения фиксируется отдельно:

- `confirmed` - источник вернул наблюдение;
    
- `not_found` - источник проверен, признак не обнаружен;
    
- `not_checked` - источник не удалось проверить или проверка не выполнялась.
    

Эти состояния имеют разный смысл для расчёта. Отрицательный результат учитывается как нулевое значение, а непроверенное наблюдение исключается из расчёта с перенормировкой весов. Полнота наблюдений показывается отдельно.

## Источники данных

|Модуль|Источник|Результат|
|---|---|---|
|`dns_collect`|Публичные DNS-разрешители|A, MX, NS, TXT, SPF и DMARC|
|`crtsh`|Журналы прозрачности сертификатов|Доменные имена, для которых выпускались сертификаты|
|`censys`|Censys Platform API|Службы, имена на IP-адресах и сведения об автономных системах|
|`dnstwist`|dnstwist|Зарегистрированные домены, похожие на домен организации|
|`fingerprint`|Главная страница организации|Технологии сайта, внешние домены и возможные поставщики|
|`zakupki`|Единая информационная система закупок|Сведения о государственных контрактах|
|`oms`|Федеральные и региональные реестры ОМС|Участие в ОМС и условия оказания медицинской помощи|

Для Censys требуется персональный токен в переменной окружения `CENSYS_TOKEN`. При этом он не сохраняется в снимках и журналах, используется только в прогоне модели.

Сведения о закупках вносятся аналитиком вручную. Данные ОМС обрабатываются из подготовленных выгрузок реестров.

## Структура проекта

|Файл или каталог|Назначение|
|---|---|
|`collect/`|Сборщики данных из открытых источников|
|`paths.py`|Пути к данным и результатам|
|`objects.py`|Загрузка перечня оцениваемых организаций|
|`features.py`|Справочник признаков и шкалы доверия|
|`reference.py`|Референсные данные и расчёт перцентилей|
|`inputs.py`|Проверка входных данных|
|`normalize.py`|Преобразование снимков в наблюдения|
|`oms.py`|Обработка реестров ОМС|
|`calc.py`|Веса и расчётные функции|
|`full_run.py`|Расчёт показателей по всей выборке|
|`run_object.py`|Сбор данных по одному объекту|
|`trace.py`|Пошаговый разбор расчёта с проверкой результата|
|`card.py`|Формирование карточки объекта|
|`exports_build.py`|Сводная таблица, лог ненайденного и карточки|
|`db.py`, `db_load.py`|Схема SQLite и загрузка наблюдений|
|`anonymize.py`|Обезличивание данных перед публикацией|
|`run_all.sh`|Последовательный запуск расчёта и экспорта|

## Запуск

Требуется Python 3 и зависимости из `requirements.txt`. Для сбора DNS используется системная утилита `dig`, для генерации доменов-двойников - `dnstwist`.

Установка зависимостей:

```
pip install -r requirements.txt
pip install dnstwist
```

Проверка входных данных:

```
python3 inputs.py
```

Расчёт по уже сохранённым снимкам из демонстрационного набора:

```
./run_all.sh
```

Этот режим не обращается к внешним источникам. Он выполняет расчёт, загружает наблюдения в SQLite и формирует результаты в `data_demo/exports/`.

Сбор данных по одному объекту:

```
python3 run_object.py --object obj-1.example --dry-run
```

`--object` принимает ключ из `objects.json`. Для реального сбора уберите `--dry-run`. Шаг Censys можно пропустить:

```
python3 run_object.py --object obj-1.example --skip-censys
```

Для обращения к Censys задайте `CENSYS_TOKEN` в переменной окружения.

Каталог данных задаётся через `TARGETMAP_DATA`. Если переменная не указана, скрипты используют каталог `data`, а `run_all.sh` по умолчанию выбирает `data_demo`.

## Входные данные

Перечень организаций и дополнительные сведения хранятся отдельно от кода.

|Файл или каталог|Содержание|
|---|---|
|`objects.json`|Объекты оценки: ключи, ИНН, домены и сведения об организациях|
|`reference.json`|Референсное распределение для расчёта перцентилей|
|`manual.json`|Данные, внесённые аналитиком: критичность услуг, связи и дополнительные наблюдения|
|`registries/`|Выгрузки реестров ОМС|

Обязательным является файл `objects.json`. Остальные входные данные могут отсутствовать: в этом случае соответствующие признаки отмечаются как непроверенные, а полнота расчёта уменьшается.

Программа проверяет наличие входных данных и показывает, какие признаки не смогут участвовать в расчёте:

```
python3 inputs.py
```

## Результаты

После выполнения `run_all.sh` в каталоге `exports/` формируются:

- сводная таблица с результатами по выборке;
- лог ненайденных и непроверенных признаков;
- отдельные карточки объектов с показателями, источниками и ограничениями оценки.

В каталоге данных также создаётся SQLite-база `observations.db`. В ней хранятся положительные, отрицательные и непроверенные наблюдения. Это позволяет отдельно анализировать результаты сбора и данные, вошедшие в расчёт.

`trace.py` показывает последовательность расчёта выбранного объекта и сверяет итоговые значения с основным расчётным модулем. При расхождении проверка завершает работу с ошибкой.

## Демонстрационный набор

В `data_demo/` находится обезличенный набор данных по семи организациям. Названия, ИНН, домены, адреса и суммы выручки заменены. Порядок значений выручки сохранён, поэтому расчётные перцентили и индексы остаются сопоставимыми с исходным набором.

Рабочие данные не публикуются. Для подготовки обезличенного набора используется:

```
python3 anonymize.py --src data --out data_demo
```

После сборки выполняется проверка, которая ищет исходные обозначения в подготовленном наборе и исходниках проекта. Если они обнаружены, программа возвращает код ошибки.

## Ограничения и безопасность

- Сбор выполняется пассивными методами по открытым источникам.
    
- При проверке сайта запрашивается только главная страница. При сетевом отказе допускается повтор запроса. Обход страниц, перебор путей и проверка уязвимостей не выполняются.
    
- Для доменов-двойников проверяются регистрация и DNS-записи. Их веб-сайты не открываются, баннеры и скриншоты не собираются.
    
- Сведения Censys зависят от доступного тарифа. Отсутствие данных в ответе не трактуется как отсутствие службы.
    
- Группа индикаторов компрометации не собирается по этическим причинам.
    
- Упоминание поставщика или размещение у него инфраструктуры само по себе не подтверждает наличие у него доступа к внутренним системам организации.
    
- Инструмент оценивает наблюдаемые признаки интереса и достижимости, а не фактическую защищённость организации и не вероятность успешной атаки.
